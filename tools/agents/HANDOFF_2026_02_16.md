## Blocker 1: RenderBuffer Shader FFP Matrix (HIGHEST IMPACT)

**~240 FFP matrix calls across 28 files.** This is THE bottleneck.

### The Problem
`rts/Rendering/GL/RenderBuffers.inl` line 15:
```glsl
gl_Position = gl_ModelViewProjectionMatrix * %s;
```
The RenderBuffer shader reads the modelview-projection matrix from OpenGL's fixed-function pipeline state. Every file that draws via RenderBuffer must first sync its CPU-side matrices to the FFP via `FlushMatrices()`:
```cpp
void FlushMatrices() const {
    glMatrixMode(GL_PROJECTION); glLoadMatrixf(projStack.Top());
    glMatrixMode(GL_MODELVIEW);  glLoadMatrixf(mvStack.Top());
}
```
This pattern exists in HUDDrawer, MiniMap, GrassDrawer, and ModelDrawerHelpers. Other files set FFP matrices directly via `glPushMatrix/glLoadMatrixf/glMultMatrixf/glPopMatrix`.

### The Fix
1. **Change the shader template** (`RenderBuffers.inl` line 8+15):
   ```glsl
   uniform mat4 transformMatrix = mat4(1.0);  // uncomment line 8
   gl_Position = transformMatrix * %s;          // replace line 15
   ```

2. **Add auto-sync in `DrawArrays`/`DrawElements`** (`RenderBuffers.h` lines 892, 916): Before `glDrawArrays`/`glDrawElements`, read the current FFP MVP and upload it:
   ```cpp
   // Auto-sync: read current FFP matrices and set uniform
   CMatrix44f proj, mv;
   glGetFloatv(GL_PROJECTION_MATRIX, &proj.md[0][0]);
   glGetFloatv(GL_MODELVIEW_MATRIX,  &mv.md[0][0]);
   CMatrix44f mvp = proj * mv;
   GetShader().SetUniformMatrix4x4<float>("transformMatrix", false, &mvp.md[0][0]);
   ```
   This makes the change **backwards compatible** — existing code that sets FFP matrices still works.

3. **Then migrate callers incrementally**: Replace `FlushMatrices()` + FFP matrix setup with direct uniform setting:
   ```cpp
   auto& sh = rb.GetShader();
   sh.Enable();
   CMatrix44f mvp = projStack.Top() * mvStack.Top();
   sh.SetUniformMatrix4x4<float>("transformMatrix", false, &mvp.md[0][0]);
   rb.DrawArrays(GL_TRIANGLES);
   ```
   Once all callers are migrated, remove the auto-sync from DrawArrays.

### Files with `FlushMatrices()` (23 call sites, 4 definitions):
- `rts/Rendering/HUDDrawer.cpp` — 6 call sites
- `rts/Game/UI/MiniMap.cpp` — 8 call sites
- `rts/Rendering/Env/GrassDrawer.cpp` — 7 call sites
- `rts/Rendering/Common/ModelDrawerHelpers.cpp` — 4 call sites (as `FlushMatricesToFFP`)

### Files with direct FFP matrix calls (no FlushMatrices, ~200 calls across 24 files):
Top files: UnitDrawer(31), GuiHandler(20), HUDDrawer(14), RoamMeshDrawer(12), WorldDrawer(11), ModernSky(10), MiniMap(10), SkyBox(9), DebugCubeMapTexture(9), MouseCursor(9), CursorIcons(9)

### Performance Note
The auto-sync via `glGetFloatv` is 2 extra GL calls per draw. This is acceptable short-term but should be removed once all callers use the uniform directly. For Metal backend, this auto-sync won't work (no FFP), so all callers MUST eventually use the uniform.

## Blocker 2: Model Shaders Read `gl_Color` (30 calls across 8 files)

**Files:** UnitDrawer(11), glStateDebug(10), HUDDrawer(2), RoamMeshDrawer(2), GuiHandler(2), WorldDrawer(1), GrassDrawer(1), CommandDrawer(1)

Model/unit shaders read the FFP vertex color via the deprecated `gl_Color` built-in. Code sets it via `glColor4f(r, g, b, a)` before draw calls.

**Fix:** Add a `uniform vec4 vertexColor = vec4(1.0)` to model shaders, replace `gl_Color` reads, then change callers to use `shader->SetUniform4f("vertexColor", r, g, b, a)`. Requires auditing which shaders read `gl_Color` (primarily the model/unit/feature shaders in `cont/base/shaders/GLSL/`).

## Blocker 3: External Textures Return Raw GLuint (~80 calls)

External subsystems return raw `GLuint` texture IDs instead of `IRHITexture*`:
- **SMFReadMap:** `GetMiniMapTexture()`, `GetHeightMapTexture()`, `GetNormalsTexture()`, `GetGrassShadingTexture()`, `GetShadingTexture()`
- **CShadowHandler:** `GetColorTextureID()`
- **IInfoTextureHandler:** `GetCurrentInfoTexture()`
- **IconHandler:** Atlas texture IDs
- **CUnitDrawer:** `GetUnitDefImage()`
- **ScopedDepthBufferCopy:** `GetDepthBufferTexture()`
- **CubeMapHandler:** `GetSpecularTextureID()`

**Fix per subsystem:** Wrap the underlying GL texture in an `IRHITexture` (using a `GLTexture` wrapper that takes ownership of an existing `GLuint`), then change the getter to return `IRHITexture*`. Callers switch from `glActiveTexture(unit) + glBindTexture(target, id)` to `texture->Bind(unit)`.

**Affected files:** GroundDecalHandler, GrassDrawer, UnitDrawer (icons), GuiHandler, SMFRenderState

---

## Blocker 4: Clip Plane Equations (~20 calls across 4 files)

`glClipPlane(GL_CLIP_PLANE0, equation)` sets a clip plane equation in the FFP. RHI has `ctx->SetClipDistanceEnabled(index, enabled)` but NO method to set the equation.

**Files:** WorldDrawer(8), MiniMap(8), UnitDrawer(8), GrassDrawer(2)

**Fix options:**
- A) Add `SetClipPlaneEquation(uint32_t index, const double* equation)` to `IRHIContext` — simple for GL, requires shader-based emulation for Metal
- B) Move to shader-based clipping with `gl_ClipDistance[i]` in vertex shaders — cleaner but requires modifying every shader that participates in clipping

---

## Blocker 5: Lua Display Lists (~12 calls across 5 files)

`glCallList(preList/postList)` executes Lua-created display lists. These are created by `LuaOpenGL.cpp` via `glGenLists/glNewList/glEndList`.

**Files:** UnitDrawer(2), FeatureDrawer(2), GrassDrawer(3), LuaMaterial(2), LocalModelPiece(1)

**Fix:** Requires Lua GL infrastructure refactor. Display lists have no modern equivalent. Options:
- Record and replay as VBO/VAO draw calls
- Deprecate display list API, provide vertex buffer alternative
- This is the lowest priority blocker as it requires significant Lua-side changes
